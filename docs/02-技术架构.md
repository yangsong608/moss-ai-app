# MOSS AI App · 技术架构（v1 草案）

> 日期：2026-10-24 ｜ 关联：[01-可行性分析](01-可行性分析.md) ｜ [03-产品设计](03-产品设计.md)
> 事实依据：`dsh-link-suite`（协议 57 方法 / 网关）、`dsh-workbench` v1.10.0（/workbench-api、SQLite 单库单 revision）、`moss-ai-app` 现状（单活跃连接）

## 0. 设计目标与总原则

1. **手机是一等公民的"离线优先"客户端**：本机 SQLite 全量可用，联网时与各台 DSH 设备双向同步。
2. **设备 = 数据域**：每台 DSH 设备的任务/日历/专注/新闻/笔记 + 会话彼此独立；手机端按 `deviceId` 分区存储。
3. **复用现有通道**：同步与 AI 都走 dsh-link 的 WSS RPC（一套认证/锁屏/限流），不新开 HTTP 面到手机。
4. **两端契约单一来源**：方法组写进 `@dsh-link/protocol`，双侧快照同步规则见 [moss-ai-app README](../README.md)（协议双份的既有约定）。

## 1. 总体架构

```
┌─────────────────────────── 手机（moss-ai-app，uni-app）───────────────────────────┐
│  UI 层     今天/日历/专注/资讯/我的 + AI 对话 + 快速捕捉（Shadow DOM 风格自绘）      │
│  业务域    tasks / calendar / focus / news / notes（移动裁剪版，见 03-产品设计）    │
│  同步引擎  SyncEngine：dirty 队列 + 周期/事件触发推拉 + 冲突合并 + 游标管理         │
│  存储层    StorageAdapter：App=plus.sqlite ｜ H5=IndexedDB（localStorage 兜底）    │
│            本地表 = 工作台镜像 + _device + _dirty + _tombstone + _updated_at       │
│  传输层    LinkPool：每设备一条 WSS（多连接并发），req/evt 复用现有帧协议            │
└──────────────────────────────────┬───────────────────────────────────────────────┘
                                   │ WSS（dshlink.v1，Bearer token per device）
┌──────────────────────────────────▼────────────── PC（每台 DSH）──────────────────┐
│  dsh-link 网关（现有）：认证/锁屏/限流/会话转发 + **新增 workbench.* 方法组**       │
│      adapters/workbench.ts → loopback HTTP → /workbench-api（无鉴权，仅回环）     │
│  dsh-workbench（需改造）：同步 API（增量拉/推、tombstone、per-entity updated_at）  │
│      数据：~/.dsh/dsh-workbench.sqlite（tasks/subtasks/logs/spaces/focus/notes/…）│
│  DSH 运行时：session.*（AI 对话/派发）、schedule/cron（新闻定时）、fs.*（笔记镜像）│
└──────────────────────────────────────────────────────────────────────────────────┘
```

**关键决策与备选**

| 决策 | 选择 | 备选与理由 |
|---|---|---|
| 同步通道 | dsh-link WSS RPC 新增 `wb.*` 方法组 | 备选：手机直连 /workbench-api——被否（无鉴权、绕开锁屏/限流、多开 HTTP 面） |
| 网关→工作台 | **loopback HTTP 调 /workbench-api** | 备选：workbench 暴露 ctx 服务被 `ctx.get` 软读——耦合更强；工作台服务面未稳定，HTTP 更松。注意既有教训：`/api/changes.*` 是 owner-only，网关调用受限（router.ts:571-576），但 `/workbench-api` 无鉴权、回环可达 |
| 手机本地库 | App：`plus.sqlite`；H5：IndexedDB 适配 | uni-app 无跨端 sqlite；H5 场景数据量小（单人任务/笔记），IndexedDB 足够 |
| 冲突模型 | 分域单主：**每个数据域（=设备）以 PC 端为权威**，手机为可写副本；改期/编辑用 `updated_at` LWW + 败者留「冲突副本」 | 备选：CRDT/字段级合并——对任务类数据过重，v1 不做 |
| 大正文传输 | 笔记 >64KB 走分块方法（或复用 BIN_FILE 512KB 通道） | 控制帧上限 256KB（frame.ts:13），大 JSON 必须分页/分块 |

## 2. 多设备数据域

**手机本地库（每表都带域列）**

```
devices(id PK, host_id, label, endpoint, token_ref, caps, lock_state, last_sync_at, cursor)
tasks(_device, id, title, status, priority, date, start, end, duration, tags, grp,
      space_id, project_path, updated_at, _dirty, _tombstone, …)
subtasks(_device, task_id, id, …)  logs(_device, …)  spaces(_device, …)
focus_sessions(_device, id, task_id, started_at, minutes, completed, _dirty)
notes(_device, id, notebook_id, title, content, tags, pinned, updated_at, _dirty, _tombstone)
notebooks(_device, id, name, workspace_path)
news_topics(_device, id, …)  news_items(_device, topic_id, hash, …)   -- 新闻以 PC 为唯一生产者
sync_state(_device, entity, cursor, last_pull_at, last_push_at)
```

- **会话域**：会话/对话本来就是 per-host（`session.list` 读本宿主实例，router.ts:280-300），手机按 deviceId 分区展示即可，无需同步。
- **聚合视图**：「全部设备」= 跨 `_device` 的只读 UNION（今天/日历/新闻）；写操作必须带目标域（默认当前切换器设备；支持「仅本机」伪域——不同步、纯手机记录）。
- **id 规则**：沿用工作台 `uid()`（时间戳+随机）即可；手机新建条目用 UUIDv4 并标 `_origin='mobile'`，推送后以服务端回执为准。

## 3. 协议扩展：`wb.*` 方法组

施工清单（dsh-link-suite 侧，9 步，细节见协议勘察）：`methods.ts` 加组+方法与 Caps（`workbench:0|1`）→ `policy.ts` 逐方法配策略（读 `P('viewer','read')`，写 `P('operator','unlocked')`）→ `dsh.ts` 声明最小类型面 → `adapters/workbench.ts` 适配层 → `router.ts` handlers（`ctx.get('workbench',false)` 软读 / loopback fetch，缺服务抛 `host/unavailable`）→ `device.info` caps 覆盖 → 自检测试自动兜底（"每个方法都有策略"、tier/role 纪律）→ `scripts/check.mjs` 全量回归 → App 侧按 policy/caps 禁用按钮。

**方法面（草案）**

| 方法 | 语义 | 策略 |
|---|---|---|
| `wb.meta.get` | 各域 revision/cursor/条数（同步前握手） | viewer/read |
| `wb.state.get` / `wb.state.put` | 全量快照（首同步/修复；复用现有 revision 语义） | viewer/read / operator/unlocked |
| `wb.delta.pull` | `{entity?, since, limit}` → `{changes[], cursor, more}`（按 updated_at + tombstone） | viewer/read |
| `wb.delta.push` | `{changes[], baseCursor}` → `{accepted[], conflicts[]}`（冲突带 current） | operator/unlocked |
| `wb.notes.get/put/delete` | 笔记实体（镜像现有 /notes 语义，保留笔记本/标签/收藏） | viewer/read · operator/unlocked |
| `wb.news.topics.list/save/delete`、`wb.news.fetchNow` | 订阅管理 + 触发检索（走既有 cron/LLM 链路） | viewer/read · operator/unlocked |
| `wb.focus.add` | 专注记账（含中断 completed=0） | operator/unlocked |
| `wb.export.get` | 全量导出 JSON（备份/迁移） | viewer/read |

> 复用：AI 对话全部走现有 `session.*`（create/list/prompt/follow/answer…），本组不重复造轮子。锁屏纪律不变：软锁下只读放行，写方法需解锁。

## 4. 同步引擎（手机侧 SyncEngine）

```
触发：启动 / 重连成功 / 前台恢复 / 定时 30s / 本地写后 5s（防抖合并）
推：  本地 _dirty 队列 → wb.delta.push（分批 ≤50 条或 ≤128KB）→ 成功清 dirty
拉：  wb.delta.pull(cursor, 分页) → 应用到本地（LWW：远端 updated_at 更新则覆盖）
冲突：push 被拒 → 服务端 current 覆盖本地，同时把本地版本存为「冲突副本」（笔记）或子待办（任务），toast 提示
删除：_tombstone=1 → push 删除 → PC 端改软删（保留 deleted_at，见 §6 改造）
游标：per (device, entity) 存 sync_state；失败退避 1s→30s，不靠重连风暴（网关建连限 10 次/分）
```

**一致性边界（诚实声明）**：v1 是"最终一致 + LWW"，不是强一致。分域单主（PC 权威）让冲突面收敛到"手机离线改 vs PC 改"一条边；跨设备不合并（数据本就分域）。

## 5. 工作台侧改造（dsh-workbench，同步前置）

| # | 改造 | 原因（现状证据） |
|---|---|---|
| 1 | **tombstone 表**（entity/id/deleted_at） | 现在 `writeState` 全清重插、删除=物理消失（index.ts:545-546），删除无法跨端传播 |
| 2 | **增量端点** `/sync/delta?since=`（updated_at 游标） | 无任何 ?since 端点；tasks/spaces/notes/news_topics 有 updated_at 可用，subtasks/logs/focus 需补 |
| 3 | **写入通道**：`/sync/push`（条目级 UPSERT）替代"整份快照覆盖"作为手机写入口 | 现 PUT /state 两设备互相冲掉（单 revision 全清重插）；PC GUI 仍可保留快照写法 |
| 4 | revision 分域化（meta 表 per-entity/per-space revision） | 现单 key `revision`（index.ts:360,617） |
| 5 | （可选）回环鉴权 header | /workbench-api 无鉴权（:3849-4204），回环内可接受，但若未来放开需 token |

> 注意：`/workbench-api` 的 GET /state 现已返回 tasks 内嵌 subtasks/attachments/logs、focus、settings（readState index.ts:493-537），字段命名 camelCase——同步层直接沿用，手机本地表按此映射。

## 6. AI 能力接入

| 能力 | 通道 | 说明 |
|---|---|---|
| 对话/执行 | `session.*`（现有） | 每设备独立会话列表；手机流式 + 工具过程 + genui 子集渲染（已修复词汇/JSON 容错两轮） |
| 上下文携带 | `session.prompt` 附引用 | 任务/笔记发起 → prompt 前缀带标题+摘要+域标识 |
| 笔记 AI 完善 | 派发 → `workbench_note_update` 回写 | 幂等（只改 title/content），手机经 delta.pull 拉回结果 |
| 新闻检索 | `wb.news.fetchNow` → 现有 `/dsh-cron` type:'llm' 任务 | PC 端跑（检索+摘要），手机只看结果；cron 不可用降级手动 |
| 专注联动 | 本地计时 + `wb.focus.add` | 结束可选"让 AI 把这轮总结进任务备注"（session.prompt） |

## 7. 传输/安全约束（来自协议现状）

- 控制帧 ≤256KB（JSON.parse 前拦 413）→ delta 必须分页；笔记大正文走分块/BIN_FILE 512KB。
- per-IP 8 连接、全局 64、建连 10 次/分——**多设备常驻连接数要预算**（3 台设备 ≈ 3 条 socket，安全）；同步失败退避，勿重连补帧。
- 认证：每设备 Bearer token（配对时一次下发、sha256 落盘）；手机侧 token 存 keystore/加密存储（uni.getStorage 加密 or 原生 keychain）。
- 锁屏：写方法 `operator/unlocked`，软锁只读——手机端按钮按共享 policy 提前置灰，caps=0 隐藏入口。
- 会话转发/审批/队列沿用现有机制，不在本期改造。
